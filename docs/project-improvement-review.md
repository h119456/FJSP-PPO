# 项目提升空间检查（2026-11-04）

本次只分析与最小复现，未改动模型、环境、配置或正在运行的dataset2训练。

## 优先纠正动态可观测性

1. `fjsp_env.py`在环境构造时使用所有工件计算duration/deformation scale与rate归一化尺度，包括未释放工件。仅改变未释放J2的参数、保留可见J1不变，当前动作normalized_duration、normalized_deformation_scale、normalized_deformation_rate及可见图节点/边特征发生变化。可使用预先声明的固定训练尺度或仅可见信息；需完整检查所有统计和缓存。
2. WAIT动作时长由包含隐藏动态事件的_next_relevant_time决定，随后进入动作normalized_duration。最小复现中，隐藏释放时间由2改3，Actor看到的WAIT时长从2改3。环境内部跳到真实事件是合理的，但策略不能提前获得真实隐藏事件的等待时长；可区分环境内部事件时间与策略可见的等待特征，仅使用已知事件/公开决策周期等可观测信息。
3. 已有测试检查未释放节点与动作不出现，但没有覆盖隐藏变量变化下的全部可见输入不变性。应增加可见信息固定、隐藏事件及隐藏工件改变的对照检查。

此前“未来事件与未释放工件完全隐藏”的项目描述不准确。当前动态结果仅在现实现下成立，修复后需重新验证；dataset2静态训练无隐藏事件，保持继续运行。

## 数据与评估

- 保留固定测试集，独立增加验证和事件专项集合；至少3个完整静态到动态的配对训练seed。
- 对同一基础实例配置无事件/释放/故障/混合及多个固定轨迹，分别汇报后按业务概率加权。
- 丰富低柔性、非均匀加工、瓶颈机、辅助机数量、成本权重、变形阈值和等待比例，检验合成规则偏好。
- 当前动态为延迟释放既有工件；若目标为连续订单流，需支持在线新工件属性、负载强度和稳定性指标。
- 区分现完整方案比较与等输入、等容量消融，报告真实训练计算量及包含构图的推理时间；现runner的inference字段在构图之后开始计时。

## 状态及预处理

- MLP的23维状态主要为均值、比例和最大值，同统计可能对应不同工序竞争关系；采用可变长工件/机器集合编码，保留MLP基线用于分离输入贡献。
- 增加绝对可见规模（工件、剩余工序、机器数）和剩余加工/关键路径/机器负载下界，避免仅比例无法表达大规模价值。
- 增加超变形阈值剩余时间窗口、工序最早可开工时间、运行操作剩余时间及资源争用；缺失信息用mask区分零值。
- 已有enhanced25提供候选相对速度、剩余工作量、机器候选压力、绝对剩余放置时间，可优先作为受控输入消融。
- 当前使用实例尺度归一化而非完全未归一化；问题在尺度可观测性、跨规模含义与信息损失。在线统计须仅用训练、跨rank同步、存入checkpoint并冻结评估；不要把故障二值和比例字段一律标准化。
- 当前时间除以max_time，使物理状态受人为截断上限影响，可考虑公开工艺时间尺度/调度下界。

## Actor

- MLP候选动作共享独立评分函数，softmax虽跨候选归一化，但每个候选的logit缺少其他候选的上下文；加入候选集合池化或注意力是优先项。
- WAIT只有时间和类型，其余候选特征近乎为零；增加公开可见的机器释放、工艺就绪及成本收益摘要，严格禁止未来事件信息。
- normal/relief/compensation候选数量不同，平坦分类分布存在组数量影响；可试类型选择加条件工件/机器选择，同时保留合法性mask并验证不会排除有用组合。
- GNN图已有两层、残差和LayerNorm，不能将这些当作尚缺组件。可试全局瓶颈注意力、动态竞争边、原机补偿关系；两层已有job和machine中转，不等于只见两道相邻工序。
- GNN固定两层的限制写在类构造器中；深度实验需调整此约束，不能仅改配置。

## Critic

- MLP Critic只看全局state，无法读取候选集合和资源配对；加入可见集合表示、规模和下界信息比盲目加宽优先。
- GNN按类型mean pooling，节点数量在readout中未显式保留；可比较mean/max与count或sum组合，保留瓶颈和规模信息。
- 价值目标以原始综合成本计量，仅优势标准化，Critic目标未做尺度自适应；可试固定公开下界缩放、ValueNorm或PopArt，严格处理尺度还原与checkpoint。
- 可比较预测相对可计算剩余成本下界的残差；多头预测剩余makespan/成本需先定义可加奖励与目标，不能直接将下界当作真实回报。
- GNN共享Actor/Critic图编码器，价值梯度也改变Actor表示；先记录两类梯度幅度/冲突，再比较独立readout、部分共享或独立编码器。
- MSE可与Huber对比；不同数据/尺度下value_loss大小不能直接代表Critic优劣，增加explained variance和验证误差。

## PPO正确性与诊断

- 当前奖励为负目标增量，gamma=1且完整正常终止时累计等于负最终目标，已有良好结构，应保留。
- collect_episode将terminated与truncated合并为done；截断没有额外失败成本。若提前停止，低累计成本可能错误地优于正常完成。需区分数值/时间上限与不可行失败：时间限制按任务语义处理bootstrap，不可行失败需显式约束/代价；不能一律bootstrap。
- 事件步长不固定但lambda按决策次数衰减；gamma=1不必改变，但需评估零时间派工动作数量与动作顺序对GAE的影响，再考虑按时间或阶段的资格迹。
- 增加approx KL、clip fraction、explained variance、梯度范数、return/advantage分布、截断率、按动作类型与事件场景指标。
- 原始熵随合法动作数量变化，可对比H/log(K)或目标熵调节；K为合法动作数且K=1须特别处理，不能未经验证直接替换当前方案。

## 吞吐

- 10回合分配到8rank，每轮有2个rank负责2回合、其余1回合，存在等待；可在后续配对实验比较16/24回合或按总决策量平衡，不在当前实验中途更改。
- 每次更新all_gather_object完整轨迹/图并在每个rank复制，Python序列化、重复构图/拷贝和每关系分支可能限制吞吐；先profile再采用张量化缓存与本地rollout优化，保持全局归一化和梯度等价。
- 验证100实例只在rank0进行，其他7卡等待，适合后续并行验证并按实例数加权汇总。

## 推荐次序

1. 修复动态信息泄露、审计截断奖励与回报处理；静态当前实验继续完成。
2. 增加诊断和统一分场景/多seed评估，建立可解释基线。
3. 输入侧优先绝对规模、时间窗口、enhanced25受控消融及Critic集合信息。
4. 改进候选交互、GNN readout和价值尺度处理，各自单变量验证。
5. profile后改进rollout分配、通信和并行验证；再评估更深网络或更复杂策略。
